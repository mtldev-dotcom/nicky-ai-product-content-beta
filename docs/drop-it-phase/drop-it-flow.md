# JUST DROP IT: Technical Flow Documentation

This document outlines the step-by-step execution flow of the **JUST DROP IT** module, from the moment a user drops content into the UI to the final product draft being saved in the database.

---

## 1. Frontend Flow (The Input Phase)

### Step 1: Input Collection
The user interacts with `src/app/create/drop-it/page.tsx` to provide any combination of:
*   **Text Blocks**: Raw text pasted into textareas.
*   **URLs**: Product links (AliExpress, Amazon, or general supplier sites).
*   **Files**: Images, CSVs, JSONs, or PDFs via drag-and-drop or file picker.

### Step 2: File Ingestion & Upload
When files are added:
1.  **Presigned URL**: The client calls `/api/media/presigned` with `forIngest: true`.
2.  **S3/R2 Upload**: The file is uploaded directly to the Cloudflare R2 bucket under the `ingest/` folder.
3.  **Local State**: The frontend stores the `publicUrl` and `mime` type for the ingest request.
4.  **Preview**: For images, a local `objectURL` is created for instant thumbnail rendering.

### Step 3: Triggering Generation
When the user clicks **"Generate Product Draft"**:
1.  The frontend filters out empty blocks and prepares a JSON payload.
2.  It sends a POST request to `/api/products/ingest`.
3.  **Progress Tracking**: The UI switches to `isGenerating` state and updates the `generationStep` badge (Classifying → Extracting → Generating → Finalizing).

---

## 2. Backend Flow (The Orchestration Phase)

The entry point is `src/app/api/products/ingest/route.ts`.

### Step 4: Authentication & Session Initialization
1.  **Auth Check**: Verifies the Supabase user session.
2.  **Org Context**: Fetches the organization's settings (OpenAI Key, Brand Voice, Active Languages).
3.  **LLM Session**: Creates a record in the `llm_sessions` table to track cost, tokens, and status across the entire pipeline.
4.  **Event Log**: Emits `INGEST_RECEIVED` to the pipeline events log.

### Step 5: Classification (`classifier.ts`)
The system analyzes the input structure:
1.  **Language Detection**: A lightweight LLM call (`gpt-4o-mini`) detects all languages present across text and URLs.
2.  **Type Mapping**: Files are identified as `image`, `csv`, `json`, etc.
3.  **Source Classification**: URLs are identified as specific platforms (AliExpress, Amazon) to guide scraping logic.

### Step 6: Evidence Extraction (`extractor.ts`)
The system pulls raw data from all sources:
1.  **URL Scraping**: 
    *   SSRF protection ensures URLs are safe.
    *   Fetches HTML and extracts **Meta Tags**, **JSON-LD (Structured Data)**, and cleaned text.
2.  **Vision API**: Images are sent to `gpt-4o-mini` with Vision to extract visible titles, colors, materials, and OCR text.
3.  **File Parsing**: 
    *   **CSVs**: Parsed into text rows.
    *   **JSONs**: Normalized into readable strings.
4.  **Information Extraction**: A centralized LLM call parses all combined raw inputs into a structured `Evidence` object (Titles, Features, Specs, Logistics).

### Step 7: Blueprint Generation (`blueprint-generator.ts`)
The final transformation:
1.  **Brand Voice Injection**: The system applies the organization's `brand_voice` and `custom_instructions`.
2.  **Mapping Rules**:
    *   **Original**: Preserves source text for languages already present.
    *   **Mixed**: Complements source text with AI expansion.
    *   **Translated**: Automatically generates missing localizations.
3.  **JSON Blueprint**: An LLM call generates a Medusa-compatible `ProductBlueprint`, including SEO metadata, logistics, and variants.
4.  **aiMeta**: Tracks exactly which fields were sourced from user input vs. generated by AI.

---

## 3. Completion Flow (The Visualization Phase)

### Step 8: Response & Persistence
1.  **Session Update**: The backend updates the `llm_sessions` status to `success` and stores a summary of the evidence and blueprint.
2.  **JSON Response**: Returns the `blueprint` and `evidence` to the frontend.

### Step 9: Loading into Store
In the frontend:
1.  `resetStore()`: Clears any previous product data.
2.  `loadFromBlueprint(data.blueprint)`: populates `useProductStore` with the new product data.
3.  **Auto-Save**: Immediately triggers `saveToDb()` to persist the draft in the `products` table in Supabase.
4.  **Redirect**: Navigates the user to `/product-details` to review the results.

### Step 10: Review & Edit
In the Product Details page:
*   **Source Badges**: The `AISourceBadge` component uses `aiMeta` to show 🟣 **AI** or 🟢 **Source** icons next to every field.
*   **Refinement**: The user can manually edit or use the "Sparkle" buttons to further enhance specific fields.

---

## Monitoring & Observability
Every step of this flow is recorded in:
*   `llm_sessions`: High-level summary and cost tracking.
*   `llm_calls`: Exact prompts and responses for every step (redacted for security).
*   `pipeline_events`: Time-stamped breadcrumbs for performance auditing.
